# Бэкенд SharedSpace

1. Найди похожий сценарий в [backend/internal/](../../backend/internal/) и проверь регистрацию маршрута в `server/router.go`. Сохраняй границы домена. Обработчик читает HTTP-запрос и формирует ответ, сервис выполняет бизнес-операцию, репозиторий работает с PostgreSQL. Подключай зависимости через существующие конструкторы и интерфейсы.
2. Проверь доступ к целевому объекту через `internal/access` и используй middleware маршрута в соответствии с его режимом доступа. Возвращай ошибки через `internal/apperror`, сохраняя согласованные статусы и формат ответа. Для работы с файлами используй `internal/storage` и существующие интерфейсы домена.
3. Для изменения схемы добавь пару следующих по номеру миграций `.up.sql` и `.down.sql` в `internal/database/migrations/`. Сохраняй применённые миграции. Проверь запуск через Compose с чистой тестовой БД и обновление БД со схемой и данными предыдущей версии. Проверь сохранность данных и поведение после повторного запуска. Подробнее в [руководстве по миграциям](../../docs/backend/migrations.md). Если операция меняет несколько записей или работает сразу с БД и MinIO, проверь границы транзакции и поведение при частичном сбое и повторе.
4. Добавь тесты рядом с кодом. Для сервиса проверь результат и ошибки зависимостей, для обработчика проверь HTTP-статус и тело с `httptest`. Если меняются права, проверь разрешённый сценарий и запрос пользователя без доступа с подставленным ID существующего чужого объекта. Для затронутого хранилища проверь интеграцию с MinIO.
5. При изменении публичного контракта проверь обработчик и DTO, обнови аннотации swaggo и выполни `make swagger` из `backend/`. Команда генерирует `backend/docs/docs.go` и `backend/docs/swagger.json`. Сверь существующие вызовы и типы в [frontend/src/api/](../../frontend/src/api/) и обнови [описание API](../../docs/backend/api-endpoints.md). Проверь, что старые запросы и данные продолжают работать в пределах согласованного контракта. Выполни проверки бэкенда из [AGENTS.md](../../AGENTS.md).

## Интеграционные проверки

Включай нужные команды в итоговый прогон из `backend/`. Задай `MINIO_ENDPOINT`, `MINIO_ACCESS_KEY` и `MINIO_SECRET_KEY` для изолированного тестового MinIO. Тест очистки сканирует и удаляет объекты в тестовом бакете. Прогон с `-v` показывает пропуски.

- Хранилище: `go test -v ./internal/storage -run '^TestStorage_UploadDownloadDelete$' -count=1`. Тест пропускается при недоступном MinIO.
- Очистка превью: задай `PREVIEW_TEST_DATABASE_URL` для тестового PostgreSQL и запусти `go test -v ./internal/files -run '^TestCleanupPreviewsIntegration$' -count=1`. Обычный CI пропускает этот тест без DSN.
- Рендеринг превью: установи ffmpeg и запусти `go test -v ./internal/files -run '^TestRenderPreview$' -count=1`.

Карта зависимостей и устройство сервера описаны в [архитектуре бэкенда](../../docs/backend/architecture.md).
