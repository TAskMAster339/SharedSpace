# Бэкенд SharedSpace

1. Найди похожий сценарий в [backend/internal/](../../backend/internal/) и проверь регистрацию маршрута в `server/router.go`. Сохраняй границы домена. Обработчик читает HTTP-запрос и формирует ответ, сервис выполняет бизнес-операцию, репозиторий работает с PostgreSQL. Подключай зависимости через существующие конструкторы и интерфейсы.
2. Проверь доступ к целевому объекту через `internal/access` и используй middleware маршрута в соответствии с его режимом доступа. Возвращай ошибки через `internal/apperror`, сохраняя согласованные статусы и формат ответа. Для работы с файлами используй `internal/storage` и существующие интерфейсы домена.
3. Для изменения схемы добавь пару следующих по номеру миграций `.up.sql` и `.down.sql` в `internal/database/migrations/`. Проверь применение на существующих данных. Если операция меняет несколько записей или работает сразу с БД и MinIO, проверь границы транзакции и поведение при частичном сбое и повторе.
4. Добавь тесты рядом с кодом. Для сервиса проверь результат и ошибки зависимостей, для обработчика проверь HTTP-статус и тело с `httptest`. Если меняются права, проверь разрешённый и запрещённый сценарии. Для затронутого хранилища проверь интеграцию с MinIO.
5. При изменении публичного контракта обнови аннотации swaggo, выполни `make swagger` из `backend/` и просмотри изменения сгенерированных файлов. Сверь клиентские типы и [описание API](../../docs/backend/api-endpoints.md). Выполни проверки бэкенда из [AGENTS.md](../../AGENTS.md).

Карта зависимостей и устройство сервера описаны в [архитектуре бэкенда](../../docs/backend/architecture.md).
