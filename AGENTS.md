# SharedSpace

SharedSpace хранит файлы и папки и позволяет делиться ими по ссылке или через совместный доступ.

## Структура проекта

- [frontend/src/](frontend/src/) — SPA на React и TypeScript. Точка входа в `index.tsx`, маршруты в `App.tsx`. Экраны лежат в `pages/`, общие компоненты в `components/`, HTTP-клиент в `api/`, состояние Zustand в `store/`.
- [backend/](backend/) — REST API на Go и chi. Точка входа в `cmd/api/main.go`, маршруты в `internal/server/router.go`. Доменные пакеты в `internal/`, миграции PostgreSQL в `internal/database/migrations/`, клиент MinIO в `internal/storage/`, артефакты Swagger в `docs/` внутри бэкенда.
- [docs/](docs/) — руководства по запуску, тестированию и устройству проекта. [Makefile](Makefile) и [docker-compose.dev.yml](docker-compose.dev.yml) задают локальный запуск. [.github/workflows/](.github/workflows/) содержит проверки и деплой.

## Работа над фичей

1. Проверь текущую ветку и рабочее дерево. Создай `feat/<краткое-название>` от согласованной базы. Если пользователь выделил ветку для этой задачи, работай в ней.
2. Уточни ожидаемый результат по запросу пользователя. Вопросы задай по тем деталям, которые влияют на поведение или приёмку и ещё не описаны.
3. Перед реализацией подготовь в корне локальный `PLAN.md`. Укажи ветку и цель, запиши короткий чек-лист действий. Для каждого пункта укажи проверяемый результат и способ проверки. Сохрани незавершённый план другой задачи перед переключением. При параллельной работе используй отдельный worktree, чтобы у каждой задачи был свой файл.
4. Покажи ТЗ пользователю и дождись его согласия. Существенное расширение объёма работы согласуй до реализации.
5. Открой [указатель скиллов](.skills/README.md) и прочитай инструкции для затронутых частей проекта. Вместе с фичей добавь или обнови тесты на новое поведение и затронутые сценарии ошибок. Обнови документацию, если изменился описанный контракт или способ работы с проектом.
6. Запусти применимые проверки. Отмечай пункты в `PLAN.md` после проверки результата. Для небольшой фичи обычно достаточно одного коммита. Если изменений много, разбей их на несколько самостоятельных проверяемых коммитов. Перед коммитом просмотри индекс и исключи посторонние правки и локальный план.
7. Когда автоматические проверки прошли, сообщи, что сделано и какие команды прошли. Для ручной приёмки подними dev-сборку через `make dev`, проверь доступность и дай адрес, точные шаги и ожидаемый результат. Для изменения API приведи воспроизводимый запрос и ожидаемый ответ. Если проверка или запуск заблокированы, назови причину и укажи, что осталось подтвердить.
8. Собери обратную связь пользователя, внеси согласованные правки и повтори затронутые проверки и ручную приёмку. После приёмки `PLAN.md` можно сохранить локально или удалить. Этот файл игнорируется Git. Даже принудительно его не добавляй.

## Проверки

Перед работой сверь команды и зависимости с текущими workflow. Запускай проверки из указанного каталога.

| Изменение | Что запустить |
| --- | --- |
| Фронтенд, [frontend.yml](.github/workflows/frontend.yml) | В `frontend/` выполни `npm install` на Node.js 22, затем `npm run lint` и `npm run format:check`. |
| Фронтенд, локально | Из `frontend/` запусти `npm test -- --watchAll=false`. Для изменений, влияющих на сборку, запусти `npm run build`. |
| Бэкенд, [backend.yml](.github/workflows/backend.yml) | В `backend/` выполни `make lint` и `go test ./...` на Go 1.26. Для полного прогона подготовь MinIO и ffmpeg как в CI. Сгенерируй Swagger через `make swagger` со `swag` v1.16.6, проверь diff и включи ожидаемые изменения в коммит. CI проверяет чистоту `backend/docs/` после повторной генерации. |
| Документация и инструкции | Проверь пути, ссылки, примеры и команды по файлам проекта. Запусти `git diff --check`. |

Для dev-сборки подготовь локальный `.env` по `.env.example`. `make dev` собирает и запускает Compose, `make dev-ps` показывает состояние сервисов. Фронтенд доступен на `http://localhost:3000`, API на `http://localhost:8080/api/v1`, Swagger UI на `http://localhost:8080/swagger/`. Подробнее в [руководстве по запуску](README.md) и [документации по тестам](docs/testing.md).
