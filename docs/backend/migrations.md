# Миграции PostgreSQL

SQL-файлы лежат в [backend/internal/database/migrations/](../../backend/internal/database/migrations/). Docker-сборка копирует их в `/app/migrations`. При запуске бэкенд ищет каталог `migrations/` относительно рабочего каталога. Если его нет, запуск продолжается без применения миграций. Для проверки миграций используй dev-сборку через `make dev` из корня репозитория.

Сервер сортирует файлы `.up.sql` по имени и применяет каждый новый файл внутри транзакции. Запись о выполнении хранится в таблице `schema_migrations` в той же транзакции. Файлы `.down.sql` хранят SQL отката для ручного применения. Сервер автоматически их не выполняет.

## Как добавить миграцию

1. Посмотри наибольший номер в каталоге миграций, возьми следующий и создай пару `<номер>_<описание>.up.sql` и `<номер>_<описание>.down.sql`. Номер дополняй нулями до трёх знаков. Для описания используй `snake_case`.
2. Изменяй схему новой миграцией. Уже применённые файлы сохраняй как есть. Учитывай существующие строки при добавлении обязательного поля или ограничения. Например, заполни старые строки перед установкой `NOT NULL`. Команды, требующие запуска вне транзакции, в том числе `CREATE INDEX CONCURRENTLY`, требуют отдельной процедуры.
3. На чистом локальном PostgreSQL запусти dev-сборку и проверь, что применились все миграции. Проверь запись новой миграции в `schema_migrations`.
4. Повтори на изолированной БД со схемой предыдущей версии и синтетическими данными. Для этого подними предыдущую версию, создай нужные данные и запусти новую версию на том же тестовом томе. Проверь данные и затронутые операции через приложение или API. Перезапусти бэкенд и убедись, что миграция повторно не выполняется.
5. Опиши порядок выкладки и восстановления для действующей установки, если изменение влияет на совместимость. Проверь ручной откат на тестовой БД, если он входит в процедуру восстановления. Для необратимого преобразования данных опиши восстановление из резервной копии.

Список миграций и их SQL находятся в [каталоге миграций](../../backend/internal/database/migrations/). Модель данных описана на странице [Сущности БД](entities.md).
