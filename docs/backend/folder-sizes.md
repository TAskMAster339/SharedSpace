# Размеры папок

Миграция `011_directory_sizes.up.sql` добавляет `directories.size_bytes` (`bigint`) и заполняет его для существующих папок. Размер включает исходные файлы во всех вложенных папках. Файлы в корзине и служебные превью не учитываются. Квота пользователя и занимаемое им место по-прежнему учитывают корзину; размер папки — отдельный показатель.

Размер возвращается в `DirectoryResponse` через уже существующие эндпоинты. Размер показывается справа в списке и над названием папки в сетке. Отдельных запросов на размер каждой папки нет.

Изменения размеров поддерживаются триггерами PostgreSQL в той же транзакции, что и изменение данных. Для загрузки, конвертации, замены размера, переноса файла, корзины и восстановления обновляются только затронутые предки. Массовые операции агрегируют изменения перед обновлением. Перенос папки использует её сохранённый размер, без чтения всех вложенных файлов. После каскадного удаления затронутые сохранившиеся предки сверяются перед фиксацией транзакции по прямым файлам и сохранённым размерам дочерних папок.

Изменения топологии дерева сериализуются с файловыми записями advisory-блокировкой в БД. Обычные файловые операции используют совместную блокировку, переносы/удаления дерева — исключительную. Чтения не блокируются этой блокировкой. Предки обновляются в согласованном порядке; блокировка берётся перед изменением квот в сервисах удаления и загрузки. Ошибки БД возвращаются через существующую обработку ошибок, а транзакции откатываются. Рекурсивные обходы защищены от зацикливания; перемещение папки в собственное поддерево дополнительно запрещено на уровне БД.

При удалении папки уже находившиеся в корзине файлы сохраняют прежнее время удаления, чтобы восстановление папки не восстанавливало их повторно.

Интеграционный тест (использует отдельную временную схему в явно указанной тестовой БД):

```sh
cd backend
TEST_DATABASE_URL='postgres://.../test_db?sslmode=disable' go test ./internal/database -run TestDirectorySizesLifecycle -v
```

Проверяются миграция и откат, заполнение существующих данных, вложенность, файлы нулевого размера, переносы файлов и папок, корзина, восстановление, окончательное удаление, удаление аккаунта, откат транзакции и параллельные загрузки с переносами. Без `TEST_DATABASE_URL` интеграционный тест пропускается. Workflow CI не изменён.

## Окно использования хранилища

Открывается по индикатору «Хранилище», кнопке с диском в директории и из меню «Ещё» на телефоне. Помимо общего расхода квоты показывает три строки: личное хранилище, общие директории и корзину. Кнопка «Открыть» ведёт в соответствующий раздел. Данные загружаются при открытии окна; при ошибке можно повторить запрос.

`GET /api/v1/users/me/storage?sort=size|name` возвращает распределение квоты только для текущего пользователя. При открытии выполняется один агрегирующий запрос с таймаутом 10 секунд, без запросов на каждую папку. Для ответа выбираются максимум 100 папок, отдельно возвращается их общее количество. Корзина входит в `used_bytes` и отдельно показана в `trash_bytes`; только окончательное удаление освобождает квоту.

Полный размер папки в списке включает всё её действующее содержимое, а окно квоты учитывает только файлы, принадлежащие текущему пользователю. Поэтому в общей папке эти значения могут различаться. Чужие файлы не увеличивают расход квоты пользователя. Строка «Общие директории» показывает собственные файлы вне личного дерева. Строка «Личное хранилище» показывает остаток квоты, занятой после вычета общих директорий и корзины из `used_bytes`, включая вложенные папки сверх лимита списка в ответе API.

Проверка распределения на отдельной тестовой БД:

```sh
cd backend
TEST_DATABASE_URL='postgres://.../test_db?sslmode=disable' go test ./internal/users -run TestStorageUsage -v
```
