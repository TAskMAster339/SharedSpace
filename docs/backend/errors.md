# Обработка ошибок API

## Структура ответа с ошибкой

Все ошибки возвращаются в едином JSON-формате:

```json
{
  "error": "Описание ошибки",
  "code": "код_ошибки"
}
```

## Коды ошибок

| Код | HTTP статус | Описание |
|-----|-------------|----------|
| `not_found` | 404 | Ресурс не найден (пользователь, файл, директория) |
| `forbidden` | 403 | Нет прав на выполнение действия |
| `unauthorized` | 401 | Неверный или отсутствующий токен |
| `conflict` | 409 | Конфликт (email/username уже занят) |
| `validation` | 400 | Ошибка валидации входных данных |
| `internal` | 500 | Внутренняя ошибка сервера |

## Типовые ошибки по эндпоинтам

### Аутентификация

| Ситуация | HTTP | Code | Сообщение |
|----------|------|------|-----------|
| Неверные email/password | 401 | `unauthorized` | Неверный email или пароль |
| Токен истёк | 401 | `unauthorized` | Токен истёк |
| Невалидный refresh token | 401 | `unauthorized` | Невалидный refresh токен |
| Email уже зарегистрирован | 409 | `conflict` | Email уже используется |
| Username занят | 409 | `conflict` | Имя пользователя уже занято |

### Файлы

| Ситуация | HTTP | Code | Сообщение |
|----------|------|------|-----------|
| Файл не найден | 404 | `not_found` | Файл не найден |
| Превышен лимит 100 MB | 400 | `validation` | Файл слишком большой |
| Нет доступа к файлу | 403 | `forbidden` | Нет доступа |
| Директория не найдена | 404 | `not_found` | Директория не найдена |
| Конвертация не поддерживается | 400 | `validation` | Конвертация из X в Y не поддерживается |

### Директории

| Ситуация | HTTP | Code | Сообщение |
|----------|------|------|-----------|
| Директория не найдена | 404 | `not_found` | Директория не найдена |
| Имя уже занято | 409 | `conflict` | Директория с таким именем уже существует |
| Превышен лимит общих папок | 400 | `validation` | Достигнут лимит общих папок |

### Совместный доступ

| Ситуация | HTTP | Code | Сообщение |
|----------|------|------|-----------|
| Пользователь не найден | 404 | `not_found` | Пользователь не найден |
| Приглашение уже отправлено | 409 | `conflict` | Пользователь уже приглашён |
| Приглашение не найдено | 404 | `not_found` | Приглашение не найдено |
| Нельзя сменить роль владельца | 403 | `forbidden` | Нельзя изменить роль владельца |

### Публичные ссылки

| Ситуация | HTTP | Code | Сообщение |
|----------|------|------|-----------|
| Ссылка не найдена | 404 | `not_found` | Ссылка не найдена |
| Срок действия истёк | 410 | `not_found` | Срок действия ссылки истёк |
| Неверный пароль | 401 | `unauthorized` | Неверный пароль |
| Превышен лимит ссылок | 400 | `validation` | Достигнут лимит публичных ссылок |

## Обработка на фронтенде

### ApiError

```typescript
class ApiError extends Error {
  status: number   // HTTP статус
  code?: string    // код ошибки (not_found, forbidden, ...)
}
```

### Паттерны обработки

```typescript
try {
  await login({ email, password });
} catch (err) {
  if (err instanceof ApiError) {
    if (err.status === 401) {
      // Неверные данные
      setFormError('Неверный email или пароль');
    } else if (err.status === 409) {
      // Конфликт
      setFieldErrors({ email: 'Email уже используется' });
    }
  }
}
```

### Автоматический refresh при 401

Если API возвращает 401 на защищённом эндпоинте, клиент автоматически:

1. Пытается обновить токен через `/auth/refresh`
2. Повторяет исходный запрос с новым токеном
3. Если refresh не удался — разлогинивает пользователя

Эндпоинты `/auth/*` исключены из этой логики (не вызывают повторный refresh).
