# Аутентификация и авторизация

## JWT-токены

Используется пара токенов: **access** (короткоживущий) и **refresh** (долгоживущий).

| Токен | TTL | Назначение |
|-------|-----|------------|
| Access | 1 час (по умолчанию) | Аутентификация запросов к API |
| Refresh | 30 дней (по умолчанию) | Обновление access-токена |

### Структура JWT

```json
{
  "sub": "user-uuid",
  "type": "access | refresh",
  "email": "user@example.com",
  "username": "username",
  "first_name": "Иван",
  "second_name": "Иванов",
  "iat": 1700000000,
  "exp": 1700003600,
  "jti": "уникальный-id-токена"
}
```

Токены подписываются алгоритмом **HMAC-SHA256** (HS256).

## Регистрация

1. Валидация входных данных (email, username, пароль)
2. Проверка уникальности email и username
3. Хэширование пароля (bcrypt)
4. Создание пользователя в БД
5. Создание корневой директории для пользователя
6. Возврат данных пользователя + токенов

**Требования к паролю:**
- Минимум 8 символов
- Максимум 72 байта
- Должен содержать заглавные и строчные буквы
- Должен содержать спецсимвол

## Логин

1. Поиск пользователя по email или username
2. Проверка пароля (bcrypt)
3. Генерация пары токенов
4. Сохранение refresh-токена в БД (с User-Agent и IP)
5. Возврат данных пользователя + токенов

## Refresh-токены (ротация)

- Refresh-токены **одноразовые**
- При каждом обновлении старый отзывается, выдаётся новый
- Токен хранится в БД в виде SHA-256 хэша

## Выход (Logout)

Отзыв указанного refresh-токена в БД.

## Контроль доступа (RBAC)

Система ролей для общих директорий:

| Роль | Действия |
|------|----------|
| `admin` | Все действия (включая управление участниками) |
| `editor` | Просмотр, скачивание, загрузка, создание папок |
| `viewer` | Просмотр, скачивание |

### Матрица разрешений

| Действие | admin | editor | viewer |
|----------|-------|--------|--------|
| view | ✓ | ✓ | ✓ |
| download | ✓ | ✓ | ✓ |
| upload | ✓ | ✓ | ✗ |
| create_folder | ✓ | ✓ | ✗ |
| delete | ✓ | ✗ | ✗ |
| invite | ✓ | ✗ | ✗ |
| change_role | ✓ | ✗ | ✗ |
| remove_member | ✓ | ✗ | ✗ |
| delete_directory | ✓ | ✗ | ✗ |
| create_link | ✓ | ✗ | ✗ |

Владелец директории всегда имеет полный доступ (все действия).
